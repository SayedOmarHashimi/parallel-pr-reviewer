# Consolidated review template

The orchestrator renders `reviews/PR-1-review.md` in exactly this shape.
`{{...}}` are substitutions; everything else is literal. This is a **template**,
not sample output — no numbers below are real.

Design constraint: the result must be **pasteable into a GitHub review box as-is**.
No JSON, no agent chatter, no "as an AI" framing. A reader who does not know Bob
produced it should read it as a thorough colleague's review.

## Notes on the format

**Severity headings are actions, not adjectives.** "Must fix before merge" /
"Should fix" / "Consider" tell the author what to do. "Critical / High / Medium"
tells them how to feel.

**Every finding carries its reviewer.** `_security_` or `_security, style_` in the
heading. This is what makes the parallel architecture legible in the output rather
than an implementation detail — a judge reading the review can see four specialists
in it.

**"Not checked" is mandatory and must not be empty.** A review that claims total
coverage is not credible. Listing the gaps is what makes the rest believable.

**"Checked and clean" earns trust.** Without it the review is a wall of complaints
and the author discounts all of it.
